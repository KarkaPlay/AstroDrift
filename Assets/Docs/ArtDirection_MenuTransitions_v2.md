# AstroDrift — Art Direction: «Menu & Transitions v2»

> Статус: визуальное направление для ТЗ Unity Developer. Технику (UI Toolkit vs Canvas) не предписываем — описана ЦЕЛЬ.
> Скоуп: только стартовый экран, панели Death/Pause/Home, переходы между ними, стартовая камера-хореография. Геймплейный HUD не трогаем (п. 6.4 — одно касание).
> Reference resolution: **1080 × 1920 (портрет)**. Все px в документе — в этой системе координат; в долях экрана дублируется как `(w × h)`, чтобы макет переносился на другие разрешения.

---

## 1. Реферс-рамка: Mini Metro

Mini Metro берём как **типографическую и композиционную** рамку, не как жанровую. Мы — аркада в реальном времени с ретроградным движением; метро-схема, маршруты, «чистый инфографический» вайб в геймплее нам не подходят.

### Берём (5 принципов)

1. **Пустота — главный элемент.** У Mini Metro экран почти всегда «дышит»: один смысловой центр на экран, всё остальное — поле. У нас: один экран = один фокус (Start → корабль; Death → счёт). Никаких блоков-карточек, плашек, рамок вокруг контента.
2. **Тонкая гротескная типографика, крупный кегль, воздух в строке.** Заголовок набран лёгким весом (Light/ExtraLight), с широким трекингом; служебный текст — мелкий, разряженный, капсом. Вес текста, а не цветовые пятна, создают иерархию.
3. **Кнопка = текст, а не объект.** Никаких «плашек». Призыв к действию — типографический (текст + микровзаимодействие: пульс яркости/трекинга, тонкая линия-индикатор). Кликабельная зона при этом ≥ 88 pt — она невидима, но велика.
4. **Анимация = скольжение по осям, easing с «выдохом».** Всё появляется/уходит через комбинацию: fade + сдвиг по вертикали + (для камеры) zoom. Кривая всегда ease-out с длинным хвостом (см. §4). Ничего не «прыгает» и не «моргает».
5. **Один акцентный цвет на весь UI.** Ч/б база + единственный акцент, который означает «живое/интерактивное/достижение». У нас акцент уже существует в системе — Gold `#FFD700` (см. §7).

### НЕ берём

- **Схемность геймплея** (линии, узлы, станции) — чужеродно для аркадной стрельбы.
- **Мультицветную инфографику** линий метро — у нас жёсткая семантика цвета уже занята (Palette.cs: белый = я/UI, красный = угроза, жёлтый = моя атака). Вторжение новых цветов в HUD сломает читаемость.
- **Строгую сетку «интерфейса-приложения»** — меню аркады может быть свободнее и поэтичнее: корабль, звёзды, пустота.

## 2. Макет стартового экрана

### Композиционная идея

Корабль **уже стоит в своей игровой стартовой позиции** (низ экрана, чуть выше нижней кромки, носом вверх) и камера приближена к нему. Он — **главный герой кадра**, а не декорация под текстом. Заголовок уходит наверх, Best — под ним мелко, CTA — в нижней трети, под кораблём, там, куда естественно падает большой палец.

### Сетка

Базовый модуль: **24 px** (при 1080×1920). Боковые поля: **96 px** (≈ 8.9 % ширины). Все тексты — по центральной оси X (одно касание, симметрия уместна).

```
┌─────────────────────────┐ 1080×1920
│  y: 300                 │
│      A S T R O          │  заголовок, Light, 96 px,
│      D R I F T          │  трекинг +12%, межстрочный 1.15
│  y: 480                 │
│      BEST 4 250         │  SecondaryText #8A8A8A,
│                         │  34 px, трекинг +8%, капс
│                         │
│      ·  звёздное поле,  │  (фон живёт, ничего не блокируем)
│        камера приближена│
│                         │
│          ▲              │  y ≈ 560 (мировая Y старта)
│         корабль         │  ЗАГОЛОВОК НЕ ПЕРЕСЕКАЕТ КОРАБЛЬ:
│  y: 1420                │  между Best (низ ~530) и носом корабля
│      ─ T A P  T O ─     │  зазор ≥ 80 px
│        P L A Y          │  CTA: 44 px, белый,
│                         │  под ним тонкая линия-индикатор
│  y: 1560                │  (см. §3), пульс §4
│                         │
│  [версия/служебное] 24px│  опционально, y: 1840, #3A3A3A
└─────────────────────────┘
```

### Зоны в долях экрана (устойчиво к разрешениям)

| Зона | Вертикаль (доля высоты) | Содержание |
|---|---|---|
| Заголовок | 0.14–0.26 | «ASTRO DRIFT», Light, 96 px, трекинг широкий |
| Best | 0.24–0.28 | 34 px, `SecondaryText`, капс, трекинг +8 % |
| Свободное поле / корабль | 0.28–0.70 | корабль в игровой позиции, звёзды |
| CTA | 0.72–0.82 | текстовый призыв + линия-индикатор |
| Служебное | 0.94–0.97 | версия, кнопка звука (если появится) — не в v1 |

**Проверка читаемости:** силуэт корабля (треугольник) читается на чёрном мгновенно; заголовок Light-весом 96 px на #000 — контраст 21:1; CTA белый 44 px — читаем с расстояния вытянутой руки. Валидно.

### Камера в меню (для разработчика — целевое состояние)

- Камера отцентрована на корабле со смещением **вверх**, чтобы корабль сидел в нижней трети кадра (композиционно «взлётная полоса» над ним).
- Приближённый зум: корабль занимает ~12–15 % высоты экрана (ориентир: в 2–2.5 раза крупнее, чем в игровом зуме). Точное значение — мировыми единицами, за разработчиком.
- Звёздное поле работает в обычном режиме (медленный дрейф) — экран живой даже без ввода.

## 3. Типографика и кнопки

### Шрифт

Сейчас — дефолт TMP (LiberationSans). Предлагаю заменить на **Inter** (SIL Open Font License 1.1 — бесплатен для любого использования, включая коммерческое; полный набор весов).

- Файл: `Inter-Regular`, `Inter-Light`, `Inter-SemiBold` (только 3 веса — не тащим всё семейство).
- TMP: статические SDF-атласы на 3 веса (одна страница, ASCII + кириллица, если потребуется локализация — отдельно).
- Fallback, если Inter по какой-то причине неудобен: **Manrope** (OFL) или **IBM Plex Sans** (OFL) — оба имеют Light и не «пластмассовые».

### Типографическая шкала (1080×1920)

| Роль | Вес | Размер | Трекинг | Цвет |
|---|---|---|---|---|
| Заголовок | Light | 96 px | +12 % | `#FFFFFF` |
| Best / служебные | Regular | 34 px | +8 % | `SecondaryText #8A8A8A` |
| CTA | Regular | 44 px | +16 % | `#FFFFFF` |
| Death: Score | Light | 88 px | +4 % | `#FFFFFF` |
| Death: Best / NEW BEST | Regular | 34 px | +8 % | `#8A8A8A` / `Gold #FFD700` |
| Кнопки Death/Pause (RETRY, HOME, RESUME) | Regular | 40 px | +16 % | `#FFFFFF` |

Правило: **иерархия через размер и вес, не через заливку цветом**. Цвет — только акцент (§7) и семантика Palette.

### CTA «TAP TO PLAY» — замена плашки

Составной текстовый элемент:

1. Текст капсом, 44 px, трекинг +16 %, белый.
2. **Под текстом — линия-индикатор**: тонкая (2 px) белая линия шириной = ширине текста, с бегущим по ней коротким ярким сегментом (40 % длины, яркий белый → хвост в `#8A8A8A`), движение слева-направо, цикл ~1.8 s. Это «пульс» Mini Metro-типа: движение, а не масштаб.
3. **Микропульс текста**: лёгкое изменение прозрачности 100 % → 72 % → 100 %, период 1.8 s, синхронно с линией. Масштаб текста НЕ анимируем (масштаб текста выглядит дёшево).
4. Кликабельная область — невидимый `RectTransform` 720 × 200 px вокруг текста (≥ 88 pt, удобно для большого пальца). Никакой подсветки при наведении (мобайл); при тапе — мгновенный отклик: текст и линия уходят по кривой выхода (§4.1).

### Кнопки Death/Pause

То же правило: текст + разделители. Вертикальный список, между пунктами тонкие линии `UiPanelFrame #2A2A2A` на ширину текста. Никаких рамок и плашек вокруг. NEW BEST — единственный цветной элемент экрана (`Gold`).

## 4. Спецификация анимаций

Общие принципы:

- Всё UI-движение — по **двум каноническим кривым** (заводим как `AnimationCurve`-константы, не подбираем на глаз в каждом месте).
- Длительности: вход 0.30–0.45 s, выход 0.20–0.30 s (выход всегда быстрее входа — экран не должен «мешкать»).
- Слои анимируются **одновременно, но со сдвигом-каскадом** 60–90 мс (UI-элементы внутри панели появляются сверху вниз с шагом 70 мс).
- Всё — с учётом времени (unscaled), пауза не должна замораживать UI-переходы.

### Канонические кривые

| Имя | Unity `AnimationCurve` (ключи) | cubic-bezier эквивалент | Применение |
|---|---|---|---|
| `EaseOutSoft` | `(0,0) (0.22,1) (0.36,1) (1,1)` — keys: `(0,0),(0.22,1),(1,1)`, outTangent плавный | `cubic-bezier(0.22, 0.61, 0.36, 1)` | всё входящее: fade, slide, camera zoom |
| `EaseInQuick` | keys: `(0,0),(1,1)`, inTangent крутой (`0.55,0,1,0.45`-поведение) | `cubic-bezier(0.55, 0, 1, 0.45)` | всё исходящее: fade-out, slide-out |

### 4.1 Старт (тап по CTA)

| Слой | Действие | Длительность | Кривая | Сдвиг |
|---|---|---|---|---|
| CTA текст + линия | fade 1→0, slide −40 px | 0.25 s | `EaseInQuick` | 0 мс |
| Заголовок + Best | fade 1→0, slide −60 px | 0.30 s | `EaseInQuick` | 70 мс |
| Камера | zoom out до игрового (§5) | 2.0 s | `EaseOutSoft` | параллельно с 0 мс |
| HUD (score, pause btn) | fade 0→1, slide +30 px | 0.35 s | `EaseOutSoft` | 1200 мс (камера почти доехала) |
| Управление | разблокировка | — | — | **t = 1.6 s** (до конца зума — игрок начинает управлять, пока камера дожимает последние 10 %) |

### 4.2 Смерть → Death panel

| Слой | Действие | Длительность | Кривая | Сдвиг |
|---|---|---|---|---|
| (взрыв/эффекты — вне скоупа, уже есть) | — | — | — | — |
| Камера | лёгкий zoom-in к месту смерти, +15 % зума, 0.4 s, без последующего движения | 0.40 s | `EaseOutSoft` | 250 мс (после вспышки взрыва) |
| Death panel: Score | fade 0→1, slide +48 px | 0.40 s | `EaseOutSoft` | 500 мс |
| Best / NEW BEST | fade 0→1, slide +32 px | 0.35 s | `EaseOutSoft` | 570 мс |
| Кнопки RETRY/HOME | fade 0→1, slide +24 px, каскад | 0.30 s | `EaseOutSoft` | 640 / 710 мс |
| HUD score | fade 1→0 | 0.20 s | `EaseInQuick` | 0 мс |

Смысл: пауза в 0.4–0.5 s между смертью и панелью даёт игроку «досмотреть» взрыв — это ритм, не задержка.

### 4.3 Retry (Death → новая игра)

См. §6 — здесь только UI-часть: Death panel целиком fade-out 0.25 s `EaseInQuick`, камера летит из «места смерти + zoom-in» обратно в стартовую позицию + приближённый зум за 0.6 s `EaseOutSoft` (см. §6), HUD fade-in 0.3 s на 0.45 s таймлайна. Управление разблокируется на t = 0.5 s.

### 4.4 Pause / Resume

| Слой | Действие | Длительность | Кривая |
|---|---|---|---|
| Оверлей затемнения | fade 0→`UiOverlay (a 0.6)` | 0.25 s | `EaseOutSoft` |
| Панель паузы (RESUME, HOME) | fade 0→1, slide +40 px | 0.30 s | `EaseOutSoft`, каскад 70 мс |
| HUD score | fade 1→0.25 (притушить, не спрятать) | 0.25 s | `EaseOutSoft` |
| Resume | обратный порядок, всё по `EaseInQuick`, выход 0.22 s | 0.22 s | — |

Игра в паузе — время стоит; анимации — unscaled.

### 4.5 Home (Pause/Death → Start)

- Панели fade-out 0.25 s `EaseInQuick`.
- Камера за 0.8 s `EaseOutSoft` возвращается в меню-позицию (приближённый зум, смещение на корабль).
- Start-элементы fade-in каскадом: заголовок (150 мс) → Best (220 мс) → CTA (300 мс), каждая 0.35 s `EaseOutSoft`.
- Никаких мгновенных `SetActive(true)` на готовых панелях — только через аниматор/tween, `SetActive` в конце выхода и в начале входа.

## 5. Хореография старта: таймлайн

Целевое состояние «до тапа» (§2): камера на корабле, приближённый зум, корабль в мировой стартовой позиции.

Таймлайн от тапа (t = 0), все значения — ориентиры для разработчика:

```
t = 0.00   Тап. CTA уходит (0.25 s), заголовок уходит (0.30 s).
           Камера начинает отъезд: zoom от «меню» к «игра», 2.0 s, EaseOutSoft.
           Корабль НЕ ДВИГАЕТСЯ — он уже на месте.
t = 0.25   Экран чист: корабль + звёзды, камера в пути (~30 % пути).
t = 1.20   Камера прошла ~80 % пути (кривая ease-out — быстрый старт, длинный хвост).
t = 1.60   УПРАВЛЕНИЕ РАЗБЛОКИРОВАНО. Игрок может начинать двигать/стрелять,
           камера дожимает последние ~10 % зума ещё 0.4 s — это незаметно,
           потому что игрок уже сосредоточен на игре.
t = 1.60   HUD fade-in 0.35 s (score, pause).
t = 2.00   Камера в игровом зуме. Геймплей полностью активен с t = 1.6.
```

Правила:

1. **Спавн астероидов/ракет стартует только с t ≥ 1.6 s** — первые 1.6 s игрок «разгоняется» в пустоте (безопасная зона). Это дизайнерское требование читаемости, не техника.
2. Камера едет по `EaseOutSoft` — начало движения должно ощущаться сразу (отклик на тап), хвост — мягкий.
3. Никакого затемнения/fade-экрана на старте — переход целиком за счёт зума и ухода UI. Чёрный фон делает это безопасным: исчезающий UI не «режет» глаз.

## 6. Хореография рестарта (бесшовность)

Проблема сейчас: рестарт телепортирует камеру/корабль и мигает панелями. Целевое поведение:

### 6.1 Смерть → Retry (основной сценарий)

1. **Без полного фейда экрана.** Полный чёрный fade читается как «загрузка» и ломает бесшовность. Вместо него — **локальный переход камеры**:
   - Из позиции «место смерти, zoom-in +15 %» (остаток §4.2) камера за 0.6 s `EaseOutSoft` перелетает в стартовую позицию меню-игры: корабль внизу, приближённый зум (тот же кадр, что был в меню перед стартом — визуальная рифма: смерть и новый забег начинаются одинаково).
   - Корабль уже стоит в стартовой позиции (respawn без анимации полёта — телепорт маскируется тем, что камера в этот момент в движении; двигающийся кадр скрывает смену содержимого кадра).
2. **Сброс мира во время движения камеры** (0–0.6 s): очистка астероидов/пуль/ракет через пул, рестарт звёздного дрейфа с обычной фазой. Игрок этого не видит как «мигание», потому что взгляд ведёт камера.
3. **UI:** Death panel fade-out 0.25 s; HUD fade-in 0.3 s на t = 0.45 s.
4. **Управление разблокировано на t = 0.5 s**; спавн угроз — с t ≥ 0.6 s (безопасная зона короче, чем при первом старте, — игрок уже «разогрет»).
5. CTA-хореография не повторяется — это не старт из меню, HUD появляется сразу.

### 6.2 Interstitial-реальность (YandexAds)

`RetryWithInterstitial` может вставить паузу на показ рекламы между тапом и рестартом. Требование к бесшовности: **после закрытия интерстишала** переход по §6.1 начинается с полного кадра «камера у места смерти» — то есть состояние сцены ДО рекламы должно сохраниться (или быть воспроизведено: место смерти + zoom-in кадр). Реклама сама по себе создаёт «моргание» вне нашего контроля — наша зона ответственности: до и после неё переходы по спецификации.

### 6.3 Home из Death

Обычный путь §4.5 (панель → камера в меню-кадр → каскад стартового UI).

### 6.4 Касание HUD (вне скоупа, но упомянуть)

HUD score появляется/уходит только fade — он не участвует в slide-хореографии, чтобы не двигать цифры перед глазами игрока. Чип множителя — вне скоупа.

## 7. Палитра

База остаётся: чёрный фон, белый, `SecondaryText #8A8A8A`, семантика `Palette.cs` не трогается (белый = я/UI, красный = угроза, жёлтый = моя атака, серый = мир).

### Предложение: один UI-акцент — `Palette.Gold #FFD700`

Gold уже в системе (цвет пуль игрока). Использовать его **исключительно** как «акцент живого/достижения» в UI:

| Место | Цвет |
|---|---|
| NEW BEST на Death-экране | `Gold` |
| CTA-линия-индикатор: бегущий яркий сегмент | `Gold` (хвост — `#8A8A8A`) |
| Чип множителя x5 (уже `Gold` в `ComboColor`) | без изменений |
| Всё остальное UI | ч/б, как сейчас |

Правило сдержанности: **не более одного золотого элемента в кадре одновременно**. Если NEW BEST и CTA-пульс не встречаются на одном экране — конфликтов нет (они и не встречаются: Start vs Death).

### Дополнение к `Palette.cs` (не ломая существующее)

```csharp
// UI-акцент v2 (Menu & Transitions) — использовать точечно, см. ArtDirection §7
public static readonly Color UiAccent = Hex("#FFD700"); // = Gold, семантический алиас
public static readonly Color UiLine = Hex("#2A2A2A");   // тонкие разделители кнопок = UiPanelFrame, алиас
```

Алиасы вводятся для читаемости ТЗ, физически это те же цвета — система палитры не меняется. Больше никаких новых цветов **не вводить**: второй акцент убьёт Mini Metro-минимализм и начнёт спорить с игровой семантикой (красный/жёлтый).

## 8. Чек-лист приёмки (для самопроверки разработчиком)

- [ ] На стартовом экране нет ни одной плашки/рамки/кнопки-объекта; только текст, корабль, звёзды, линия-индикатор.
- [ ] Корабль стоит в игровой стартовой позиции уже в меню; заголовок не пересекает его.
- [ ] От тапа до управления ≤ 1.6 s; движение камеры начинается в кадре < 100 мс (отклик мгновенный).
- [ ] Первый спавн угроз — не раньше t = 1.6 s (старт) / 0.6 s (рестарт).
- [ ] Рестарт: ни одного мгновенного `SetActive` на видимой панели, ни одного телепорта камеры на глазах; полный чёрный fade не используется.
- [ ] Все переходы — по двум каноническим кривым §4; выход всегда быстрее входа.
- [ ] Шрифт Inter (OFL), 3 веса, статические TMP SDF-атласы; LiberationSans в UI не остаётся.
- [ ] NEW BEST и золотой сегмент CTA — единственные золотые элементы; одновременно в кадре один.
- [ ] Всё анимируется в unscaled time (пауза не замораживает UI-переходы).
- [ ] Читаемость на 5" экране: заголовок, Best, CTA различимы без приближения; CTA-зона тапа ≥ 88 pt.
